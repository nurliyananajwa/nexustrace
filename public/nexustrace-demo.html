See how it works
The problem

Most project trouble starts with a requirement nobody kept track of.

A requirement changes. The test does not.

Your supervisor updates a feature in week 8. The old test still passes, so nobody notices the new version was never checked.

Gaps hide in spreadsheets.

Requirements live in one file and tests in another. Nobody can say which features are untested until the demo goes wrong.

Vague wording cannot be tested.

"The system should be fast." How fast? Without a number, nobody can prove the requirement was met.
